# Qwen3.5-0.8B below Q4_0 (measurements, 2026-10-21)

> **Status, 2026-10-22: answered — no quant below Q4_0 is faster, so none is a candidate; Q4_0 stays.**
> Speed (§0) was measured first on resuming, since it gates the question; the remaining accuracy runs
> (UD-IQ2_XXS, IQ1_M, IQ1_S) were then dropped as unable to change the outcome. Nothing adopted.

## 0. Speed (laptop CPU, `llama-bench -dev none -t 8 -p 512 -n 128 -r 3`, tok/s, 2026-10-22)

| quant | read 512 (pass 1) | write (pass 1) | read 512 (recheck) | write (recheck) |
|---|---|---|---|---|
| **Q4_0** | **387** | **54.4** | **303** | **48.9** |
| Q3_K_M | 201 | 49.4 | 226 | 49.5 |
| UD-Q2_K_XL | 144 | 45.9 | — | — |
| UD-IQ2_XXS | 102 | 42.5 | 103 | 43.0 |
| IQ1_M | 121 | 44.0 | — | — |
| IQ1_S | 126 | 44.7 | — | — |

- **The laptop ran on battery** (AC 0) and pass 1 ran Q4_0 first; between passes Q4_0 itself fell
  387 → 303 / 54.4 → 48.9. The recheck ran in reverse order (Q4_0 last): **Q3_K_M only ties Q4_0 at
  writing and reads ~25% slower; everything below 3 bits is slower at both.** Logs:
  `quants-out/bench-cpu-*.log`, `bench-cpu-recheck.log`.
- Why: the files barely shrink (§2) and the low-bit formats cost more arithmetic to unpack. The phone
  has repacked kernels for even fewer of them (§4.2), so no gain is expected there either.
- **GPU numbers are not usable:** ~10 tok/s writing for every quant, also with `-dev Vulkan1` (the
  default splits layers onto the Intel UHD as well: two Vulkan devices). The RTX 3050 sat in P8 at
  210 MHz on battery. `bench-gpu-*.log`, `bench-gpu3050.log`. Not investigated: it cannot change the
  outcome.
- **Next lossless lever:** speculative decoding (speed study §3.4; DeepSeek's DeepInfer calls its own
  "DSpark"): greedy output is unchanged by construction, so accuracy is not at stake, only writing
  speed. Unmeasured.

**The owner:** *"did we test our smallest qwen with lower bits as well? Would it be faster?"*, then
*"we can benchmark accuracy and speed here"*, *"I am concerned about low bit cases below q4_0 … not
the high ones"*, *"start testing them (from 3 to 2) in parallel"*, *"also q1"*.

**How.** Laptop (i7-11800H, RTX 3050 Laptop 4 GB), the Vulkan runtime formicaria ships (b10076),
the four text evals on the GPU with thinking off, exactly as `chain2.sh` ran Q4_0/Q8_0 on 2026-10-19
(`pixi run eval`, `EVAL_NO_RECORD=1`). Files from `unsloth/Qwen3.5-0.8B-GGUF`, SHA-256 checked;
**no 1-bit file is published**, so IQ1_M/IQ1_S were made here with `llama-quantize` from its BF16
and unsloth's own imatrix (plain llama.cpp IQ1, not a UD mix). Raw data and scripts in
`~/bench-scratch/quants-out/` and `~/bench-scratch/keep/scripts/quants-*.sh`.

## 1. Accuracy (laptop GPU, one lane at a time, no timeouts in any log)

| eval | **Q4_0** (4.5 bpw, 507 MB) | **Q3_K_M** (470 MB) | **UD-Q2_K_XL** (418 MB) |
|---|---|---|---|
| meetings, constrained (production) | **13/17** | 9/17 | **13/17** |
| meetings, free (well-formed) | 13/17 (17) | 6/17 (13) | 10/17 (9) |
| research, exact / grounded | 4/8 / 8/8 | 6/8 / 7/8 | 2/8 / 8/8 |
| edits | 3/7 | 3/7 | 3/7 |
| recipe, constrained: exact / found of 257 / invented | **15 / 245 / 2** | 7 / 136 / 3 | *(stopped mid-run)* |
| recipe, free: exact / found / invented | 16 / 237 / 1 | 6 / 81 / 2 | **1 / 17 / 1** |

- **Q4_0 reproduces 2026-10-19 exactly** on every eval, so these rows compare with the speed study's
  §2.3 despite the code changes since (Myrme 0.7.1).
- **Recipe, the long-answer eval, breaks first:** 245 → 136 ingredients at 3 bits (constrained),
  17 at 2 bits (free). By hand both low-bit models loop (§3).
- **The UD 2-bit beats plain 3-bit on meetings** (13 vs 9 constrained): unsloth's dynamic mix keeps
  sensitive layers higher, which matters more than the mean bit count for short grammar-led answers.
- **The grammar hides much of the damage:** free 2-bit meetings answers are well-formed 9/17,
  constrained 17/17.
- Research (8 cases) and edits (7) are too small to separate the quants.

## 2. Why lower bits barely shrink this model

From `llama-quantize`'s own log for IQ1_S: the **vocabulary table** (248,320 × 1,024, tied with the
output, ~⅓ of all parameters) stays at **Q5_K, ~175 MB, 57% of the 304 MB file**; 153 matrices are
IQ1_S, 6 IQ2_XXS, 28 Q2–Q5. Overall **3.39 bpw** (IQ1_M 3.48). So the "1-bit" file is only ~40%
smaller than Q4_0, which caps any writing-speed gain (writing reads every weight per token).

## 3. Hand-checked answers (one request each, temperature 0, `smoke-*.json`)

- Q4_0: meeting right; pancakes loop ("cinnamon / nutmeg") to the 300-token limit.
- Q3_K_M: says "not fixed", then gives the right details; "1/2 cup salt".
- UD-Q2_K_XL: meeting right but invents the year 2024; ingredients and the whole answer repeat.
- **UD-IQ2_XXS ignores `enable_thinking:false`:** it opens its own `<think>` and repeats one sentence
  to the limit. Expect it slow and near zero.

## Mistake in this session, kept so it is not repeated

- **Parallel eval lanes on one 4 GB GPU corrupted the results.** Six lanes (four servers at once,
  each with 32 spinning threads) drove the load to 32 with the GPU at 21%; requests hit the client's
  120 s timeout (`openai.rs`) and scored as wrong — Q4_0 found 0 recipe ingredients instead of 237.
  The logs are in `quants-out/invalid-parallel/`. **One eval server at a time on this laptop.**
- The first downloader had no stall timeout and hung ~50 min on one file; `--speed-limit 20000
  --speed-time 60` fixed it.
