# Myrme 0.6.0 — a faster phone model, an accurate one to choose, and quicker mail on the laptop (contract 1.5)

## What changes for people using formicaria

- **The phone's assistant answers faster.** The phone's default is now the same model at 4-bit
  (`lfm2.5-vl-450m-q4`): it writes about 65% faster on the phone (59 words-pieces a second against
  36), so a recipe takes about 9 s instead of 14, with the same scores on every text test. A phone
  that already has the assistant keeps its model and is *offered* the faster one in Settings, with
  its size (0.42 GB); nothing is downloaded unasked.
- **A more accurate model for the phone, as a choice** (`qwen3.5-0.8b`, 0.71 GB, Apache-2.0),
  labelled *"More accurate, slower"*. It finds meetings in 13 of 17 test threads instead of 5,
  places note edits the faster one cannot, and finds 245 of 257 recipe ingredients instead of 102.
  Text answers are slower (a recipe about 31 s); a handwritten page is read in a median 28 s, with
  about half the errors. The phone's chooser that shows these words is formicaria's next change.
- **The laptop's mail pass is quicker and finds a meeting more.** With qwen3-vl-4b, the meetings and
  the title questions share one prompt, so naming the conversation no longer reads the whole
  exchange again (about 500 tokens instead of 4,000 on a long thread). Meetings found: 16 of 17 test
  threads, up from 15.

## What changes for formicaria (contract 1.5, an addition)

- `Manifest::phone_choices` lists the models a phone may choose between; each `Model` carries a
  `phone_label`, the words to show. The catalogue's `default_mobile` is `lfm2.5-vl-450m-q4`.
- Catalogue keys `phone_label`, `thinking` (`false` turns a model's thinking off; both launchers
  pass it) and `shared_mail_prompt` (the mail layout, per model). `Agent` gains the field
  `shared_mail_prompt`, filled from the catalogue by Myrme's own launchers.
- Nothing is renamed or removed. An app built for contract 1.4 links this release unchanged.

## Checked

- The speed study (`docs/research/2026-10-19-speed.md`): every model and setting measured on the
  Dimensity 7300 phone and the laptop, with the accuracy of each candidate on the method evals.
- **A new eval for the conversation title** (`methods/meetings/eval/titles.json`, 12 cases): the
  mail layout was chosen per model on it and the meetings eval (qwen3-vl-4b 16/17 and 12/12 shared;
  the 450M keeps its own prompt, 5/17 and 9/12, because shared it names the mailbox's owner).
- Unit tests pin the phone choices, their checksums and sizes, the thinking-off flag on the phone's
  command, and both mail calls sharing one system prompt. `pixi run ci` and `pixi run integration`
  pass.

## For developers

- The meetings and title evals take `FM_LAYOUT` (`old`, `first`, `b`, `c`) and default to the
  model's own layout, so an eval measures what ships.
- `docs/research/2026-10-19-improving-the-fast-model.md`: how prompting and fine-tuning could make
  the fast phone model more accurate, with a first experiment.
