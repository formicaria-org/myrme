# Myrme 0.11.0 — four commands, and a reply you can read as it is written (contract 1.9)

## What changes for people using formicaria

- **Four commands, the same on every device:** `/research`, `/propose`, `/transcribe` and `/recipe`.
  `/search` was a second way to the web that was hard to tell from `/research`. A typed `/search`
  still works and means `/research`. In a discussion that belongs to no note, `/research` answers
  there from the web, as `/search` did.
- **A chat reply shows while it is written.** The text so far appears where the "writing the
  reply" wheel is, about once a second, and the reply replaces it when it lands. It needs formicaria
  0.20. With an older formicaria the wheel shows as before.
- **The phone's model rereads far less of a conversation.** Qwen3.5-0.8B now runs with a 128-token
  micro-batch. Measured on a laptop CPU:
  - a later chat turn reads ~320 tokens instead of 705–967, and its first word comes in ~0.9 s
    instead of 1.7–2.4 s;
  - the first turn costs 3% more;
  - photos read the same.

## What changes for formicaria

- **Contract 1.9**, an addition:
  - `VaultAccess::activity_draft(disc, text)`, a provided method that does nothing. It is the reply
    so far, sent at most once a second.
  - The desktop's `FmServe` sends it to `/api/agent_activity` as `{discussion, stage: "writing the
    reply", draft}`. A formicaria that does not know `draft` reads the stage alone.
  - The phone's vault may keep it for its own `agent_activity_poll`.
- **A catalogue key**, `ubatch` (per model), passed as `-ub` by `Manifest::add_template_flags`.
  It is set for `qwen3.5-0.8b`.
- **Not in the contract:** `Command::Chat` and `Command::Propose` lose their `search` field, and
  `/search` parses as research.

## Checked

- **Unit tests:**
  - commands: `/search` is research, and research wins over a proposal;
  - a first-class discussion is a self-anchored `thread_of`;
  - the micro-batch reaches the command only for a model that asks;
  - streamed responses read whole however they are split across reads;
  - a streamed answer is shown as it grows, over a loopback socket.
- **`pixi run integration`**, with a new test in which a model streams a chat reply slowly:
  - against formicaria with drafts (`FM_CHECKOUT`), the poll shows the reply so far before it
    lands, and then the reply is posted whole;
  - against the pinned formicaria, the poll has no draft and the reply still lands.
- **Speed**, on a laptop CPU (`docs/research/2026-10-25-minimum-speed.md` §5, and
  `agents/chat-speed.py`): three chat turns on a 1,500-token note, with first tokens at 4.7, 0.9
  and 1.4 s.
- **Not adopted**, measured on the 30-recipe eval:
  - recipe by pointing (14/30 against 17/30);
  - n-gram drafting (no gain).
- **The phone** is checked at release.
