# Myrme 0.7.0 — Qwen on the phone, an OCR for printed pages, and meetings already over (contract 1.6)

## What changes for people using formicaria

- **The phone runs Qwen3.5-0.8B, and only that.**
  - The faster 450M model is no longer offered. It found none of four meetings in the owner's own
    mail, read handwriting at 96% word error and printed pages at 49%.
  - Qwen3.5-0.8B (0.71 GB, Apache-2.0) found two of the four meetings and invents none in threads
    with no meeting. It reads handwriting at about 44% word error and printed pages at 2.3%.
  - A phone still running the 450M keeps it and is *offered* Qwen3.5-0.8B with its size; nothing is
    downloaded unasked. With one model there is no chooser any more.
- **Printed pages are read by an OCR** (PP-OCRv6 small, Apache-2.0) on Linux, macOS and the phone.
  - It reads a printed page in about a second on a laptop, at 0.8% word error over 30 test pages.
  - It runs first on every page. Its text is kept when its confidence is 0.97 or more, which was
    every printed test page and no handwritten one. Otherwise the vision model reads the page, as
    before.
  - **It gives plain lines:** a printed table or code block comes back as text lines, not as a
    Markdown table or an indented block.
  - Windows has no OCR yet: Microsoft's Windows archive of ONNX Runtime is 78 MB for a 14 MB library,
    so Windows reads every page with the vision model.
- **A meeting that has already happened is not proposed again.** A reply sent after a call (17:31,
  after the 17:00 call) used to make larger models report that call as fixed. A meeting is now past
  once it began before the newest email was sent.

## What changes for formicaria (contract 1.6, an addition)

- **Stage ONNX Runtime into the APK.** The catalogue pins Microsoft's android-arm64 AAR
  (`runtime_url_onnxruntime_android_arm64` with its SHA-256). formicaria's packaging puts its
  `jni/arm64-v8a/libonnxruntime.so` into `jniLibs` as `host::BUNDLED_ONNXRUNTIME`
  (`ci/android-stage-onnxruntime.sh`, ~19 MB). Without it the phone works as before, with no OCR.
- **On a computer nothing changes in formicaria.**
  - `Tools::provision`, `Tools::provision_weights` and `Tools::refresh_runtime` fetch the OCR's
    files (~31 MB) and ONNX Runtime (~8–10 MB archive) into `<tools dir>/ocr/`.
  - `Tools::runtime_outdated` is `true` while they are missing, so an existing install gets them
    through the runtime refresh it already runs, without fetching the model runtime again.
- **What `Tools::bytes` and `Tools::remove` cover:** both include `ocr/`.
- **`Agent::ocr`** is new; both launchers fill it. formicaria builds no `Agent`.
- **The catalogue:**
  - `default_mobile` is now `qwen3.5-0.8b`, the only `phone_label`.
  - New keys: `ocr_<file|url|sha256|bytes>_<det|rec|dict>`, `runtime_url_onnxruntime_<platform>` and
    `onnxruntime_lib_<platform>`.
- Nothing is renamed or removed. An app built for contract 1.5 links this release unchanged; the
  phone's OCR needs the staging script.

## Checked

- **The OCR through the install path** (`tests/live_ocr.rs`): fetched and verified from the
  catalogue's pins, ONNX Runtime opened at run time, the image eval's pages read.

  | Pages (30 each) | WER | Confident | Time a page (laptop CPU) |
  |---|---|---|---|
  | Printed | 0.8% | 30 | 0.96 s |
  | Handwritten | 61.3% | 0 | 0.65 s |

  So every handwritten page goes to the vision model.
- **The reading turn** (unit test): a confident reading stands and names the OCR; an unsure one goes
  to the vision model; with no vision model the OCR's reading stands.
- **The Android build:** `fm-agent-run` with the OCR cross-compiles for `aarch64-linux-android` with
  formicaria's NDK, and Microsoft's `libonnxruntime.so` needs only libc, libm, libdl and liblog.
- **Model choice:**
  - `docs/research/2026-10-20-small-model-benchmark-summary.md` covers every measurement behind the
    phone model, including a user's real mail (private, scores only).
  - `docs/research/2026-10-19-scouting-phone-models.md` §4 covers the leaderboard shortlist.
- **The past rule:** every answer recorded in `methods/meetings/eval/cases.json` scores the same
  under it, and real mail moves only for the two models that reported the past meeting.
- `pixi run ci` (cargo-deny included) and `pixi run integration` pass.

## For developers

- **cargo-deny:** two crate-scoped licence exceptions (`clipper2-rust`, BSL-1.0; `libfuzzer-sys`,
  NCSA) and two documented waivers for *unmaintained* notices (`paste`, `ttf-parser`), all from the
  OCR's image stack.
- **The meetings eval** reads a private case file through `FM_EVAL_CASES` and never records into it.
- **`examples/ocr_page.rs`** reads page images with the OCR and prints time and confidence per page.
