# Myrme 0.1.0 — the first release from its own repository

Myrme is formicaria's on-device assistant. This first release moves it out of the formicaria
repository with its history, gives every method an evaluation, and switches to a faster runtime that
holds the model's answers to the exact form each task needs.

## What changes for people using formicaria

- **Answers are held to a schema.** The runtime is Myrme's own llama.cpp build with llguidance
  (release `runtime-llg-3`), on Linux, macOS, Windows and Android. The model's output is constrained
  to the structure each method needs, so it cannot drift into free text. About 17% faster on a GPU
  and 20% on a CPU than the previous runtime, with the same results.
- **Research says when it cannot answer.** Its answer starts with whether the sources answer the
  question at all (8/8 on both laptop models, up from 7/8).
- **Note edits are anchored.** A proposed edit points at the place it changes instead of rewriting
  the whole note, so nothing outside it is lost (7/7 on both laptop models).
- **Reading handwriting on a laptop works.** The image reader is capped at 1024 image tokens: pages
  that all timed out now read at a 17.9% median word error rate, about 35 s a page.

## Measured

Every method has an evaluation in `methods/<name>/eval/`, scored on its structured output and run
the way the app runs it:

| Method | Data | Result |
|---|---|---|
| Meetings from mail | 17 cases | 17/17 (qwen3-4b-2507) |
| Research | 8 cases | 8/8 |
| Note edits | 7 cases | 7/7 |
| Handwriting (image → text) | 30 GNHK pages | 17.9% median WER |
| Speech (audio → text) | 60 MLS + LibriSpeech clips | ggml-base 6.3% EN / 36.1% IT; ggml-small 4.1% / 23.1% |
| Recipes | 30 Wikibooks recipes | 28/30 |

The evaluation data is openly licensed and pinned by revision and hash; each set carries its notice.

## Known limits

- The phone's image model cannot read handwriting (82.7% median WER).
- Italian speech with `ggml-base` is weak (36.1% WER); *better listening* (`ggml-small`) helps.
