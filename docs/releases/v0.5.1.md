# Myrme 0.5.1 — the phone's model gets the context window it needs (contract 1.4)

## What changes for people using formicaria

- **Reading a photo on the phone has room again.** The phone started its model with the catalogue's
  general 2048-token window instead of the 4096 the phone model asks for. One photo is about 1027
  tokens, so a picture together with the note and the conversation could leave too little room for
  the answer. The phone now uses each model's own window, as the desktop always did.

## Checked

A unit test pins the phone's server command to the model's own window. Found while researching
Myrme's speed (`docs/research/2026-10-19-speed.md`).

## For developers

- **`pixi run eval-speed`** runs the method evals against one model and prints a table of the
  server's own timings per method: prompt tokens, prefill and decode rates, seconds per request.
  Speed changes are measured with it the way accuracy changes are measured with `pixi run eval`.
- **The evals can run on a phone over USB:** with `EVAL_ADB_DIR` set, `agents/eval.sh` starts
  llama-server on the device from that folder and forwards its port. `EVAL_CTX` sets the window,
  `EVAL_NO_RECORD` leaves `cases.json` alone, and `EVAL_SERVER_LOG` keeps the timings.
- The image eval reads pages from `FM_EVAL_IMAGES` when set, to measure what an image size costs
  in accuracy.
